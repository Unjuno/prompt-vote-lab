# Repository cleanup inventory

## Purpose

This inventory turns the repository 5S policy into a concrete cleanup map.

It is intentionally conservative. It classifies files before deletion.

No file should be deleted only because it looks old. Deletion requires a protected-evidence check, a canonical/legacy check, and a passing cleanup PR.

Do not delete protected public evidence casually.

## Inventory states

| State | Meaning | Default action |
|---|---|---|
| Protected evidence | Public or audit evidence that must remain inspectable | Keep |
| Canonical active | Current implementation, policy, or operator surface | Keep and harden |
| Legacy script | Non-canonical manual diagnostic / historical fallback script | Keep unless a separate removal gate passes |
| Historical archive evidence | Old canary-era or policy evidence that still explains past decisions | Keep, label historical, and do not cite as current status |
| Generated snapshot | Machine-written public output derived from repository or GitHub state | Keep unless regenerated by the owning workflow |
| Retired legacy launch scaffolding | Obsolete launch path replaced by canonical evidence | Remove only with docs/tests updated |
| Cleanup candidate | Candidate for consolidation, relabeling, or later removal | Track before changing |
| Not-yet-removable | Should eventually be removed, but only after a separate removal gate | Keep until the gate is satisfied |

## Historical archive evidence

Historical archive evidence explains past canary decisions, model-policy transitions, run records, and migration boundaries.

It is not active canonical status.

Canary-era names should be preserved when they identify old evidence:

```text
first-canary
canary-007
canary-008
canary-009
isolated-3file
writeback-canary
offline-json-canary
policy-agent-canary
task-packet-canary
fixed-issue-instruction-canary
```

Archive cleanup rule:

```text
Do not rename canary-era evidence just to make it look current.
Do not delete canary-era evidence just because the current canonical runner is different.
Do not cite historical archive evidence as current canonical evidence unless the canonical marker is present.
Do keep links from docs or run records so the history remains auditable.
```

A cleanup PR that touches historical archive evidence should state:

```text
Historical evidence role:
Current active role, if any:
Canonical status claim: none / explicit marker present
Affected run records:
Affected public docs:
Affected contract tests:
Replacement evidence path:
Rollback path:
```

## Generated snapshots

Generated snapshots are not source-of-truth policy. They should be changed by their owning generator or workflow.

| Surface | Path | Owning flow |
|---|---|---|
| Public result JSON | `data/public-results.json` | Public Results Export |
| Public result Markdown | `data/public-results.md` | Public Results Export |
| Comparison dashboards | `lab/comparisons/**` | Comparison dashboard builder |
| History pages | `lab/history/**` | Public results or dashboard builder |
| Support unlock records | `data/support-unlocks/*.json` | Support Unlock Export |
| Run records | `runs/*.md` | Weekly or manual run logging |

Cleanup PRs should not hand-edit generated snapshots unless the PR is explicitly a generated snapshot update.
