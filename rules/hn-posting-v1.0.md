# hn-posting-v1.0

## Purpose

This rule defines how Prompt Vote Lab should be posted to Hacker News.

## Principle

Do not post the same pitch every week.

Each HN post should be tied to a concrete weekly result:

- a voted prompt
- a Codex implementation PR
- a merge or reject decision
- an expectation-gap classification
- an analysis note

## Minimum bar before posting

A weekly HN post should have at least one of:

- a completed Codex implementation PR
- a clear failure worth analyzing
- a comparison between rank-1 and support-unlocked rank-2 or rank-3
- a new rule or process change caused by an observed failure

## Avoid

- reposting the same project description every week
- posting before a run has a result
- framing support as buying merge rights
- claiming success without a reviewed PR
- hiding failures

## Recommended HN formats

Use one of:

- Show HN: Prompt Vote Lab — Week XXX result
- Ask HN: How would you evaluate this prompt-voting coding experiment?
- Tell HN: What we learned from Week XXX of Prompt Vote Lab

## Weekly post structure

1. One-sentence summary
2. Selected prompt and vote rank
3. PR link
4. Result classification
5. What changed in the rules or process
6. One specific question for readers

## Cadence

Weekly posting is allowed only if the post contains a new result.

If a week has no meaningful result, skip HN and write only the repo log.
