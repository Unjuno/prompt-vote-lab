# support-unlocked-runs-v1.1

## Purpose

Support-unlocked runs allow additional ranked candidates to be attempted as comparison runs during the current weekly vote.

Support is fuel for comparison. It is not a purchase of success, adoption, merge, maintenance, review, support work, or specification control.

## Weekly candidates

Each weekly vote may produce ranked candidates:

- rank 1: normal weekly run
- rank 2: optional support-unlocked comparison run
- rank 3: optional support-unlocked comparison run

## Supported one-time tiers

- 5 USD: Support Rank 2 Comparison Run
- 10 USD: Support Rank 3 Comparison Run

There is no general support tier.

## Initial thresholds

- rank 2 comparison run: 5 USD total weekly support
- rank 3 comparison run: 10 USD total weekly support

The 10 USD threshold is total weekly support, not 5 USD plus 10 USD.

These thresholds are experimental and may change.

## Scope

Support applies to the current weekly vote only.

Old weekly candidates are not automatically reopened.

Support does not create:

- a request channel
- a paid review obligation
- a maintenance contract
- a delivery promise
- a support obligation
- merge rights
- specification control

## No-change baseline interaction

Support does not override the no-change baseline.

Additional comparison runs can only happen after the weekly candidate set has passed the baseline rule.

## Safety policy

Support opens an additional experiment attempt only.

All support-unlocked runs must still follow:

- `static-ui-v1.0`
- `agent-run-policy-v1.0`
- `merge-policy-v1.0`
- maintainer review
- PR-only workflow

## Continuation

A support-unlocked comparison run may itself end as partial, stalled, budget-capped, unsafe, failed, or completed.

Continuation is not purchased by support.

Continuation must be explicit and justified under `agent-run-policy-v1.0`.

## Naming

Use ranked names:

- `week-XXX-rank-1`
- `week-XXX-rank-2`
- `week-XXX-rank-3`
