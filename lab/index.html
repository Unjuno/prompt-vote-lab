Prompt Vote Lab

People propose and vote on prompts in GitHub Issues. A fixed low-cost implementation model edits this constrained lab UI, and we record the gap between expected and actual results.

Weekly threshold

A prompt must beat the no-change baseline

Every weekly vote includes a virtual candidate with 20 votes: No change this week. If that baseline ranks first, the workflow records the vote summary but does not create implementation PRs or spend API budget.

Participate

Prompt submission and voting happen on GitHub. This static page does not store submissions or votes directly; it shows the experiment, current candidates, run process, and reviewed outcomes.

1. Propose

Create a GitHub issue with the prompt you want the implementation model to run.

2. Vote

Use 👍 reactions on prompt proposal issues. A real prompt must beat the 20-vote no-change baseline to trigger implementation.

3. Review

Compare the PR, safety check, and expectation-gap result after implementation.

Support-unlocked runs

Support can unlock extra comparison runs

The rank-1 prompt is the normal weekly implementation candidate after the no-change baseline is beaten. Support may unlock rank-2 and rank-3 as additional comparison runs for the current weekly vote.
