Public prompt experiment

Prompt Vote Lab

A public experiment where people propose prompts, vote with GitHub reactions, and a fixed low-cost AI coding agent implements selected prompts inside a constrained static lab.

What this is

A prompt market plus a constrained implementation sandbox

Participants submit prompt candidates as GitHub Issues. Votes rank those prompts. If a real prompt beats the weekly no-change baseline, the implementation model edits only lab/index.html, lab/style.css, and lab/app.js.

What this is not

It is not a feature-request queue, a paid merge system, or a general-purpose web app builder. Merge remains manual after review.

Weekly threshold

A prompt must beat the no-change baseline

Every weekly vote includes a virtual candidate: No change this week. It starts with 20 virtual votes. If that baseline ranks first, the workflow records the vote summary but creates no implementation PR and spends no API budget.

Loop

How the experiment runs

1. Propose

Create a GitHub Issue with the exact prompt and expected visible result.

2. Vote

Use 👍 reactions. A real prompt must beat the 20-vote baseline before implementation.

3. Implement

A fixed gpt-5-nano implementation run edits only the static lab files.

4. Review

Safety checks run. The maintainer reviews the implementation PR and decides merge or reject.

5. Classify

The result is classified by expectation gap: hit, partial, misread, overbuild, underbuild, conflict, unsafe, or rejected.

6. Record

The run summary, PR, safety result, and final classification are recorded for comparison.
